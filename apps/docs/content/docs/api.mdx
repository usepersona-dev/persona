The app is a client of this API. What the app does, you can do over HTTP. The persona's own tools call the same use cases, with the same limits.

## Authentication

Every endpoint takes one of two credentials:

- **An API key.** Send `Authorization: Bearer persona_sk_...`. A key belongs to an organization and reaches everything in it. It shows once, when you make it. Persona stores only its hash.
- **The app's session.** The app calls the API with the signed-in person's Clerk session.

```bash
curl -H "Authorization: Bearer $PERSONA_KEY" https://app.usepersona.dev/api/projects
```

Three kinds of address take no credential, because the address holds it: the vault's collect links, `/api/collect/{token}`; a published file's details, `GET /api/files/{fileId}`; and a webhook's address, `/eve/v1/webhooks/{secret}` (see [Webhooks](#webhooks)).

## Requests and answers

- Send a body as a JSON object. An empty body counts as `{}`.
- A success answers `200` with JSON, or `204` with no body when there is nothing to return, as after a delete.
- Times are ISO 8601 strings.
- Ids are strings. Most are 24 lowercase characters.
- Lists and creates sit under their parent, such as `/api/personas/{personaId}/skills`. One item has its own path, such as `/api/skills/{skillId}`.

## Errors

A failure answers with a status and `{ "error": { "code", "message" } }`. The message is plain English, written for a person.

| Status | Code | When |
| --- | --- | --- |
| `400` | `invalid` | The body or a value is not valid. |
| `401` | `unauthorized` | No credential, or a credential that is not valid. |
| `404` | `not_found` | Nothing with that id, or it belongs to another organization. |
| `409` | `conflict` | A name is taken, or the thing already exists. |
| `500` | `server_error` | Something failed on our side. |

## Projects

| Method and path | Body | Answer |
| --- | --- | --- |
| `GET /api/projects` | | the organization's projects, oldest first |
| `POST /api/projects` | `{ name, description?, imageUrl? }` | `{ project, persona }`: the project and its first persona |
| `GET /api/projects/{projectId}` | | the project |
| `PATCH /api/projects/{projectId}` | `{ name?, description?, imageUrl? }`. `null` clears the description or the picture. | the project |
| `DELETE /api/projects/{projectId}` | | `204`. It deletes the personas, numbers, bots and links too. |

`name` is 1 to 80 characters and `description` up to 500.

### Pictures

| Method and path | Body | Answer |
| --- | --- | --- |
| `POST /api/uploads` | `{ contentType }`: `image/png`, `image/jpeg`, `image/webp` or `image/gif` | `{ url, uploadUrl }` |

`PUT` the picture to `uploadUrl` with the same `Content-Type`, within 10 minutes. Then send `url` as a project's or a persona's `imageUrl`.

## Personas

| Method and path | Body | Answer |
| --- | --- | --- |
| `GET /api/projects/{projectId}/personas` | | the project's personas |
| `POST /api/projects/{projectId}/personas` | `{ name, imageUrl? }` | the persona |
| `GET /api/personas/{personaId}` | | the persona |
| `PATCH /api/personas/{personaId}` | `{ name?, imageUrl?, models? }`. `imageUrl: null` removes the picture, so the face is made from the name again. `models` is a list of up to five `{ model, when }`, each `when` (1 to 500 characters, required on every model) saying when to pick that model; `models: null` goes back to the default pair. | the persona |
| `DELETE /api/personas/{personaId}` | | `204`. It also deletes its files, app accounts and secrets. |
| `POST /api/personas/{personaId}/duplicate` | `{ name? }` | the copy |
| `GET /api/models` | | the gateway's language models a persona can run on |

`name` is 1 to 80 characters. A model is a gateway id, such as `anthropic/claude-sonnet-5.5`.

## MCP servers

| Method and path | Body | Answer |
| --- | --- | --- |
| `GET /api/personas/{personaId}/connections` | | the servers, each with `headers` as a list of names |
| `POST /api/personas/{personaId}/connections` | `{ name, url, description?, headers?, enabled? }` | the server |
| `PATCH /api/connections/{connectionId}` | `{ name?, url?, description?, headers?, enabled? }` | the server |
| `DELETE /api/connections/{connectionId}` | | `204` |
| `POST /api/connections/check` | `{ url, headers? }` or `{ connectionId, url?, headers? }` | `{ ok: true, server, tools }` or `{ ok: false, reason, message }` |

`headers` is an object of header names and values. Values never come back. In a `PATCH`, a string sets a header, `null` removes it, and a header you leave out stays. A check with `connectionId` uses the saved server with `url` and `headers` merged on top in the same way, so you can check a change before you save it. `reason` is `unauthorized`, `not-mcp` or `unreachable`.

## Vault

| Method and path | Body | Answer |
| --- | --- | --- |
| `GET /api/personas/{personaId}/credentials` | | the credentials, each with `filled`: the names of its filled fields |
| `POST /api/personas/{personaId}/credentials` | `{ title, description?, fields }` | the credential |
| `PATCH /api/credentials/{credentialId}` | `{ title?, description?, fields? }` | the credential. Values of removed fields are deleted. |
| `DELETE /api/credentials/{credentialId}` | | `204` |
| `PUT /api/credentials/{credentialId}/values` | `{ "<field>": "value" or null }` | `{ filled }` |
| `POST /api/credentials/{credentialId}/collect-link` | | `{ token, url, expiresAt }` |

`fields` is a list of 1 to 30 `{ name, secret }`, each name unique. A value is up to 4,000 characters, and no answer ever holds one.

### Collect links

A collect link lets a person fill a credential in without an account. It works for 24 hours, more than once.

| Method and path | Body | Answer |
| --- | --- | --- |
| `GET /api/collect/{token}` | | `{ title, description, fields, expiresAt, persona }`. Each field has `name`, `secret` and `filled`; `persona` has `name` and `imageUrl`. |
| `POST /api/collect/{token}` | `{ "<field>": "value" }` | `{ filled }`. An empty string keeps the stored value. |

An expired link answers `400`. A token that was changed answers `404`.

## Files

| Method and path | Body | Answer |
| --- | --- | --- |
| `GET /api/personas/{personaId}/files` | | the persona's files, newest first |
| `POST /api/personas/{personaId}/files/upload` | `{ name, contentType }` | `{ fileId, uploadUrl }` |
| `POST /api/personas/{personaId}/files` | `{ fileId, name }` | the file |
| `GET /api/files/{fileId}` | | `{ id, name, contentType, size, public, createdAt, url, persona }`, with a signed `url` that lasts 15 to 30 minutes and the persona's `name` and `imageUrl`. A published file answers without a credential; a private one only to its org's members. |
| `PATCH /api/files/{fileId}` | `{ name?, public? }`. `public: true` publishes the file; `false` makes it private again. | the file |
| `POST /api/files/{fileId}/upload` | `{ contentType }` | `{ uploadUrl }`, to replace the content |
| `PUT /api/files/{fileId}` | | the file, after its new content is uploaded |
| `DELETE /api/files/{fileId}` | | `204` |

To upload: ask for an `uploadUrl`, `PUT` the bytes to it with the same `Content-Type` within 10 minutes, then `POST` the `fileId` to finish. Persona reads the type and the size from storage. A file is up to 2 GB.

## Automations

| Method and path | Body | Answer |
| --- | --- | --- |
| `GET /api/personas/{personaId}/automations` | | the automations, oldest first |
| `POST /api/personas/{personaId}/automations` | `{ name, prompt, cron or at, timezone? }` | the automation |
| `PATCH /api/automations/{automationId}` | `{ name?, prompt?, cron?, at?, timezone?, enabled? }` | the automation |
| `DELETE /api/automations/{automationId}` | | `204`. Its runs stay; one running right now finishes. |
| `GET /api/automations/{automationId}/runs?limit={limit}` | | the runs, newest first. `limit` is 1 to 100, 50 by default. |

Give `cron`, `at`, or both; a `PATCH` keeps what it does not name, and `null` clears one, as long as one stays.

A run has `scheduledFor`, `status` (`running`, `completed` or `failed`), `result` (`{ summary, notify }`), `sessionId` and `endedAt`.

```bash
curl -X POST -H "Authorization: Bearer $PERSONA_KEY" -H "Content-Type: application/json" \
  -d '{ "name": "Monday plan", "prompt": "Write a plan for the week from the calendar.", "cron": "0 9 * * 1", "timezone": "Europe/Berlin" }' \
  https://app.usepersona.dev/api/personas/$PERSONA/automations
```

## Webhooks

| Method and path | Body | Answer |
| --- | --- | --- |
| `GET /api/personas/{personaId}/webhooks` | | the webhooks, oldest first, each with its `url` |
| `POST /api/personas/{personaId}/webhooks` | `{ name, prompt }` | the webhook, with its `url` |
| `PATCH /api/webhooks/{webhookId}` | `{ name?, prompt?, enabled? }` | the webhook |
| `DELETE /api/webhooks/{webhookId}` | | `204`. Its address stops working; its runs stay. |

`name` is 1 to 80 characters and `prompt` 1 to 20,000.

Another app calls the webhook at its `url`, `https://app.usepersona.dev/eve/v1/webhooks/{secret}`, with no other credential:

| Method and path | Body | Answer |
| --- | --- | --- |
| `POST /eve/v1/webhooks/{secret}` | anything, such as JSON or text | `202` with `{ ok, runId }`. A paused or deleted webhook answers `404` with `{ "error": "This webhook does not exist." }`: here `error` is a string, not the object of [Errors](#errors). |

The body reaches the persona as a file. [Personas](/personas#webhooks) tells how a run goes.

## Tools

| Method and path | Body | Answer |
| --- | --- | --- |
| `GET /api/personas/{personaId}/tools` | | the persona's tools: an object with one `{ enabled, deferred }` per name, such as `{ "browser": { "enabled": true, "deferred": false }, ... }` |
| `PATCH /api/personas/{personaId}/tools/{name}` | `{ enabled?, deferred? }` | all the tools, after the change |

`name` is one of `apps`, `automation`, `browser`, `file`, `instruction`, `mcp`, `media_audio`, `media_images`, `media_read`, `media_video`, `model`, `note`, `skill`, `trigger`, `vault` and `webhook`. Any other name answers `400`. A tool that was never changed is on and not deferred. [Personas](/personas#tools) tells what each name covers and what the two settings do.

```bash
curl -X PATCH -H "Authorization: Bearer $PERSONA_KEY" -H "Content-Type: application/json" \
  -d '{ "deferred": true }' \
  https://app.usepersona.dev/api/personas/$PERSONA/tools/browser
```

### Links

| Method and path | Body | Answer |
| --- | --- | --- |
| `GET /api/personas/{personaId}/link-codes` | | the codes that still work |
| `POST /api/personas/{personaId}/link-codes` | | `{ code, personaId, expiresAt, createdAt }` |
| `DELETE /api/link-codes/{code}` | | `204` |

`channel` is `whatsapp_meta` (a WhatsApp number on Meta) or `telegram`. ## The agent

The agent has its own HTTP API at `/eve/v1/*`, on the same origin. It takes an agent token, not an API key.

| Method and path | Answer |
| --- | --- |
| `POST /api/personas/{personaId}/agent-token` | `{ token, expiresAt }`: a token for this persona, good for 15 minutes |
| `POST /eve/v1/session` with `{ message }` | `{ ok, sessionId, deliveryId }`: a new chat |
| `POST /eve/v1/session/{sessionId}` with `{ message }` | a follow-up in that chat |
| `GET /eve/v1/session/{sessionId}/stream` | the chat's events, one JSON object per line |
| `POST /eve/v1/session/{sessionId}/cancel` | stops the turn that is running |
| `POST /eve/v1/session/{sessionId}/clear` | forgets the conversation so far, keeps the session |
| `POST /eve/v1/session/{sessionId}/compact` | compacts the conversation into a summary |
| `POST /eve/v1/session/{sessionId}/end` | ends the session |

Send the token as `Authorization: Bearer <token>` on each `/eve/v1/` call. The routes are eve's: see the [eve channel docs](https://eve.dev/docs/channels/eve) for every route and event.
